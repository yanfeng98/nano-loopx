# LoopX Self-Repair 模式


把本文件用作紧凑诊断表。每当真实事件教给一个可复用的控制面教训时，添加一行。

| 模式 | 症状 | 需读证据 | 可能根因 | 持久修复 |
| --- | --- | --- | --- | --- |
| `narrative_delivery_authority_leak` | 改写运行标签把已解决工作变成 blocker，或把准备变成必需跟进；无类型历史积累交付债务。 | 显式 outcome/kind/scale、范围进度观察、紧凑历史，以及仅叙述变更前后 status/quota 决策。 | 关键词推断与"未知即失败"连击把叙述提升为机器权威。 | 使用显式 typed 语义与既有范围 blocker 谓词；unknown 破除证据连击。删除关键词回退，标签仅保留用于展示，并通过 CLI 测试负向叙述变更与正向 typed 义务。 |
| `periodic_report_todo_log_editorial_gap` | 阶段报告生成并被冻结，但产物是英文 Todo 年表，报告构建工作挤占业务发现，或页面缺少清晰的概览到深度分析主线。 | 冻结产物与语言、投影的已完成/打开 Todo 事实、report-meta 动作种类、编辑来源与段落顺序、因果/边界细节、事实引用与批准 gate 创建时间。 | 受管消费者把持久 Todo 散文当作可发布文案，并让渲染器从时间戳或通用内容种类推断叙述结构。因此生成正确性证明了持久性与权威，但没有证明编辑质量。 | 为精确意图冻结紧凑公开安全检查事实请求，要求 Agent 用 typed `overview -> problem map -> causal analysis -> coverage/actions -> next actions` 契约撰写中文编辑，在消费者中验证语言密度与事实谱系，编辑响应通过前不创建冻结产物或批准 gate。report-meta 工作放在业务叙述之外，发布保留为稍后精确负载权威关卡。 |
| `periodic_report_stage_boundary_premature_promotion` | 周期报告在设置工作、若干普通 Todo 完成或一次 replan 后生成，即使预期的分析或交付 vision 仍开放。 | Goal-vision 修订、材料性结果检查点与证据 refs、replan 触发种类、被接受的语义增量、继任者前沿归属或终态 Goal、报告触发 receipt、渲染产物计数。 | 运行时聚合把 Todo 量或任何 replan 当作有意义阶段边界证据，而非区分成功路径 vision 关闭与恢复/继续规划。 | 把阶段完成推导为自主 replan 的严格成功孪生：要求证据链接的已关闭 vision 加持久落定的继任者前沿或终态 Goal，按 closed-vision/前沿身份去重，并拒绝普通完成加 blocker、停滞、长链与 monitor replan。生成、发布与公告保持单独权威层。 |
| `periodic_report_post_writeback_hook_authority_gap` | 周期报告生产者可被手动调用，或通用 quota/回读代码导入报告政策，但已提交写回未通过 capability 生命周期产生回放安全的 typed 意图。 | 主持久 receipt 与结算身份、组合根激活、TS hook 注册/输入/结果/sidecar receipts、回放时 provider 调用次数、意图写范围、外部效果计数。 | Capability 政策与通用控制面生命周期耦合，或自动路径依赖尽力而为诊断事件而没有 typed 写回后检查点。 | 在核心所有的 TS hook 边界保留注册、接纳、receipt 验证、确定性排序、失败隔离与 sidecar 回放；阶段政策与触发评估留在 capability；只从组合根显式启用配置注册；发出幂等无效果意图并要求单独受管生成与发布权威。 |
| `periodic_report_terminal_closeout_hook_gap` | Quota 或 status 之后证明验证过的无跟进，但不存在周期报告候选且 monitor heartbeat 保持安静。 | 最后一次材料性刷新、最终 Todo 完成 receipt 与结算身份、写回后 hook 事件种类、终态前沿投影、sidecar receipts、外部效果计数。 | Hook 只在完成前刷新运行；持久 Todo 完成事务此后形成终态前沿但没有派发写回后 capability hooks。 | 把持久 `todo_complete` 接纳为 typed 写回后事件，仅在完成验证、持久化与结算回读成功后派发，从已提交状态重建最终前沿，并保留回放安全无效果意图 receipts。无验证阶段关闭时普通完成与仅观察监控不足。 |
| `pending_capability_intent_projection_gap` | 持久写回后 sidecar 说 `intent_recorded`，但 quota 保持 `monitor_quiet_skip` 或 `terminal_no_followup`；没有受管执行器唤醒，因此不出现本地产物或精确批准 Todo。 | 精确 Goal/Agent sidecar、意图 schema 与权威、消费 receipt、quota 交互契约、生成产物计数、批准 Todo 计数、外部效果计数。 | 生产者日志持久但没有读模型把未消费能力意图投影进 quota 仲裁。终态或安静生命周期因此永远隐藏了必需能力工作。 | 添加 provider-neutral TypeScript 验证的待处理意图交互槽，让 opt-in capability 只读取精确合格 sidecar，并让待处理动作优先于 quiet/terminal 路由。通过幂等本地执行器消费，它冻结已检查产物与一个摘要绑定用户 gate；外部交付保持未授权，回放时抑制已消费意图。 |
| `approved_capability_delivery_successor_gap` | 受管报告或其他 capability 负载被冻结且其精确用户 gate 已批准，但 quota 返回安静 terminal/monitor 状态且无 provider 动作运行。之后调用方也可能即兴定目的地或默认发送者，因为批准 receipt 不含可执行路由。 | 冻结生成/消费 receipt、已完成的 gate 决策与范围、链接的 agent Todo、批准前后必需决策范围、Goal Channel 绑定、所选 Todo、provider 效果与精确发送者/目标回读。 | 消费者只创建了用户 gate。批准记录了权威但没有显式链接、typed 的 agent 继任者供 Todo/quota 选择，因此外部效果只存在于聊天记忆或调用方惯例中。 | Gate 前创建一个绑定冻结生成、精确决策范围、provider capability 与安全写范围的 blocked agent 继任者；用 `unblocks_todo_id` 链接 gate。批准必须原子消费仅该范围并恢复继任者。provider 随后从持久项目绑定解析路由与发送者，拒绝调用方覆盖/默认回退，并仅在原生效果回读后记录成功。 |
| `turn_replay_recovery_semantic_gap` | 真实 Turn 从安全 Journal 前缀恢复，但 `inspect-journal` 把 `replay_legal=false` 呈现为禁止恢复；仅 scheduler 或保存 Host 结果的恢复特别误导。 | Journal 完整性字段、回放决策、执行器采纳的恢复决策、已完成阶段前缀、完整 typed 结算身份、权威所选 Todo 谱系、条件 Host Session Binding 检查、prepared-effect 存在、有界恢复结果。 | 无效果终态回放与有效果执行器恢复被折叠成一个用户面对决策，即使执行器使用不同 status/phase 规则；初始修复也省略结算身份或其绑定到 Turn 的交叉检查，使漂移的 goal、agent 或规范 Todo 到达后续效果。 | 保持回放合法性与 Journal 一致性区分。让一个 typed 恢复决策成为执行器与检查都使用的源；授权前验证并交叉绑定规范结算 goal、agent、Turn 实例、绑定与效果 id，包括所选 Todo 或自适应主 Todo；投影继续/恢复阶段/Host 重调/原因及仅参与的检查，并持久化有界计划对实际审计。用零 provider 调用回归覆盖身份与绑定漂移。保留既有 prepared-effect 回读所有者，不声称通用 exactly-once 语义。 |
| `managed_chat_resume_turn_identity_gap` | 受管 Chat Session 在其适配器不健康后恢复、返回 `ready` 并清除 `active_turn_id`，但被打断的 Turn 保持非终态且无主。 | 恢复前 Session 快照、prepare 后持久化 Session、适配器健康、被打断 Turn 状态与错误码、最终 Session 状态。 | 恢复准备在适配器恢复前清除了持久活动 Turn 引用，然后恢复只重读已变异 Session 并丢失了恢复前的 Turn 身份。 | 携带变更前 Turn id 通过新鲜关闭状态检查，在恢复 Session 前把该 Turn 终态化为 `failed/server_restarted`，并用聚焦回归覆盖不健康适配器恢复，同时保留每 Session 生命周期锁。 |
| `dashboard_chat_stdio_encoding_gap` | Dashboard Chat 完成 ASCII 轮次但 Codex app-server 在 Windows 上因非 ASCII 输入关闭；直接 stderr 报告无效 UTF-8。 | 失败的多语言请求、app-server stderr、Python locale 编码、app-server `Popen` 文本管道选项、同一请求在显式 UTF-8 控制下。 | 文本模式 stdio 管道继承了 Windows 系统代码页，即使 app-server JSON-RPC 传输要求 UTF-8。 | 在 app-server 子进程管道上显式设置 `encoding="utf-8"`，并保留聚焦启动契约回归，使宿主 locale 不能改变协议编码。 |
| `provider_capacity_terminalization_gap` | 模型 provider 报告临时容量耗尽或过载，但适配器只存通用非零退出，每个失败 Turn 直接路由到手动修复；重复重启也可能无持久限制地重试。 | Provider 错误事件与 stderr 适配器、公开失败类别、Turn Journal 尝试计数、恢复决策检查、控制器处置、quota/写回 receipts、恢复前后所选模型。 | 结构化 provider 代码、模型容量、服务器过载、定时速率限制与硬计划/账单 quota 耗尽被折叠成散文再折叠成单一通用修复或重试结果。 | 适配器边界优先精确结构化代码，未知存在代码时失败关闭，仅在无代码时使用有界诊断文本。保持模型容量、provider 过载、定时速率限制或无代码 HTTP 429、不可重试硬 quota 区分；特定 quota 代码必须胜过 HTTP 429。Host 调用前持久化尝试，仅对瞬时类别附加同配置有界重试，让 TypeScript Journal 决策拒绝伪造或耗尽的预算，并投影带显式退避的无效果控制器等待。观察到不透明会话时保留 Session Binding，失败不消耗 quota，绝不隐式切换模型，并覆盖真实协议 envelope 形状、优先级冲突、回放、耗尽与私有文本不持久化。 |

| `host_plugin_system_python_mutation_gap` | 插件 bootstrap 在开发者机器上成功，但干净 Debian 或类似受管宿主以 externally-managed-environment 错误拒绝 `pip install`，因此宿主启动时没有承诺的 skill。 | 干净镜像中的打包插件启动、所选 Python 版本与固定 pip argv、受管运行时文件、就绪结算、首个宿主原生 skill 目录、下游 Driver/GoalBar 命令解析。 | Python 版本可用性被当作变更该解释器系统环境的许可；单元 fake 验证了 argv 流但没有验证宿主包管理边界。 | 安装进插件拥有的 `--target` 目录，通过受管启动器调用，并让每个插件界面解析同一运行时。绝不使用 `--break-system-packages`。保留打包干净容器冒烟，无需模型凭据证明启动就绪与首目录可见。 |
