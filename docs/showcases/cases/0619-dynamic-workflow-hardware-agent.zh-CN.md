# 0619:面向硬件 Agent 开发的动态工作流

> [English](0619-dynamic-workflow-hardware-agent.md)

## 摘要

这篇配套说明解释了这个交互式硬件-agent 工作流案例的公开安全边界:

[打开交互式案例页面。](0619-dynamic-workflow-hardware-agent.html)

该案例描述的是围绕模糊、长程硬件开发目标(goal)展开的动态工作流:生成的脚本协调有界的 worker-agent 动作,而 LoopX 把 goal、quota、todo 所有权、验证证据和运行历史稳定地保持在任何一个聊天线程之外。

## 现在能说的内容

这个案例之所以有用,是因为它指向与基准案例不同的案例展示(family)分支:

- goal 是开放式的,而不是一次固定的基准运行;
- 该领域有专门的工程约束;
- 多个 agent 需要对所有权、状态和收敛有共享视图;
- 产品故事是"动态工作流",而不是单条 CLI 命令;
- 公开工件现在包含五个公开安全的硬件案例,覆盖封闭验证、时序优化、设计空间探索、Fmax 优化和收敛到工程下限。

## 要突出的 LoopX 行为

这个公开案例突出了 LoopX 如何帮助:

- 在长程模糊 goal 上保持持久状态;
- Agent 所有权与交接,而不是不透明的并行工作;
- 通过共享 todo、证据、配额和审查边界实现进展收敛;
- 操作者对"什么需要决定"与"什么可以继续"的可见性。

## 证据边界

不要发布原始聊天、截图、专有设计细节、内部工具名、私有仓库、本地路径、任务 id 或未公开的硬件工件。公开声明应停留在产品模式与公开案例层面,除非贡献者明确批准更深入的脱敏证据。

## 公开工件

交互式 HTML 页面是静态公开工件。它可以直接从仓库打开,也可以作为前场页面捆绑(前场 Pages bundle)的一部分托管。它不是可运行的硬件基准,不应被呈现为可复现的 EDA 工作流。

## 公开证据序列

1. 一个模糊的工程 goal 需要不止一个 worker agent。
2. LoopX 给这些 agent 提供共享状态与所有权界面。
3. 生成的脚本把有界工作分发给专业化的 worker。
4. 工作通过被认领的 todo、验证证据和一条主审查路径收敛。
