# 每两周更新说明：2026-06-28 至 2026-07-11


## 来源边界

本说明概括从 2026-06-28 到 2026-07-11 的公开仓库历史。它使用公开 commits、pull requests、
releases、已交付文档、示例与 smoke 测试。它排除私有 operator 状态、原始 benchmark 证据、
私有链接、本地路径与凭证。

## 亮点

- 发布了 [LoopX v0.2.0](https://github.com/huangruiteng/loopx/releases/tag/v0.2.0)，完成了
  peer-agent runtime cutover，并把 claims 定义为软路由与 writeback 信号，而不是 runtime
  authority。
- 把 issue-fix 从补丁生成扩展成一个维护者循环，包含仓库上下文、feasibility、CI 与验收证据、
  reviewer 路由、PR 生命周期观察与 durable 结果 writeback。
- 让 Explore 与 Explore Harness 对真实长程工作更有用：可恢复实验、聚焦图导出、独立 lanes、
  语义主题亲和与资源感知的 portfolio 规划。
- 把 Auto Research 转成真实工作区上可见的证据循环，带基于角色的轮次、自动唤醒、摘要证据
  writeback 与显式的 promotion 或 continuation frontiers。
- 通过类型化 todo continuations、peer routing、紧凑 quota 载荷、selected-todo projection，
  以及更可靠的 monitor、vision 与 quota-spend 转换，减少了控制面歧义。

## 交付内容

### LoopX v0.2：Peer Agents，而不是 Runtime 层级

[v0.2.0](https://github.com/huangruiteng/loopx/releases/tag/v0.2.0) 把 peer-agent 模型确立为公开
控制面契约。一个 claim 现在回答的是谁被期望采取下一步并写回结果；quota、gates、capabilities、
exclusions 与 write scope 仍然决定执行是否被允许。该 release 还用类型化 continuation 与独立
handoff 契约取代了特殊的 reviewer-lane 假设。

代表性变更：

- [#1787](https://github.com/huangruiteng/loopx/pull/1787) 把 runtime 切换到 peer agents。
- [#1773](https://github.com/huangruiteng/loopx/pull/1773) 添加了类型化 todo continuation
  策略。
- [#1867](https://github.com/huangruiteng/loopx/pull/1867) 在 peer 重新分配下保留了 due-monitor
  路由。
- [#1852](https://github.com/huangruiteng/loopx/pull/1852) 验证并发布了 v0.2.0 release。

### Issue-Fix 成为维护者循环

Issue-fix 路径现在承载了首个代码变更之后的工作。它可以把仓库上下文带入规划、捕获首次 push 的
CI 与验收证据、带 fallback 地路由 reviewer 请求、观察 merge 状态，并把结果写入领域生命周期。
仓库记忆也被收窄到决策有用的上下文，而不是未分化的历史。

代表性变更：

- [#1780](https://github.com/huangruiteng/loopx/pull/1780) 为 issue-fix 工作流添加了调用方仓库
  上下文。
- [#1835](https://github.com/huangruiteng/loopx/pull/1835) 添加了一个可选的 OpenViking context
  provider，且没有把它变成控制面依赖。
- [#1865](https://github.com/huangruiteng/loopx/pull/1865) 改进了 reviewer 上下文，而
  [#1876](https://github.com/huangruiteng/loopx/pull/1876) 捕获了首次 push 的 CI 证据。
- [#1883](https://github.com/huangruiteng/loopx/pull/1883) 投影了 merged-PR 事件，使依赖工作可以
  恢复。
- [#1887](https://github.com/huangruiteng/loopx/pull/1887) 让仓库记忆对 issue 修复决策有用。

### Explore 与 Auto Research 变得可恢复

Explore 获得了保留真实拓扑同时支持聚焦 owner 视图的图投影。独立实验 lanes 与语义主题亲和
在投影后保留，portfolio 规划可以计入有限资源，而不是把每个分支都按无限容量排序。Explore
Harness 也成为可配置、可恢复的，而不是一次性的实验。

Auto Research 从一个脚本化演示走向真实 KNN 工作区上可见的多 Agent 循环。虚假指标被移除；
轮次现在保留角色归属、摘要证据、自动唤醒与显式的下一 frontier。

代表性变更：

- [#1785](https://github.com/huangruiteng/loopx/pull/1785) 让 Explore Harness 可配置且可恢复。
- [#1804](https://github.com/huangruiteng/loopx/pull/1804) 添加了聚焦的 Explore 图导出；
  [#1859](https://github.com/huangruiteng/loopx/pull/1859) 保留了独立 lanes；
  [#1863](https://github.com/huangruiteng/loopx/pull/1863) 添加了资源感知的 portfolio 规划。
- [#1448](https://github.com/huangruiteng/loopx/pull/1448) 移除了虚假的 Auto Research 指标，
  [#1455](https://github.com/huangruiteng/loopx/pull/1455) 把 KNN demo 移到真实 benchmark
  工作区。
- [#1590](https://github.com/huangruiteng/loopx/pull/1590) 启用了自动唤醒，而
  [#1677](https://github.com/huangruiteng/loopx/pull/1677) 简化了可见 frontier 投影。

### 控制面状态更易读、更可信

该时间段收紧了围绕 todos、monitors、vision、quota 与 scheduler 决策的状态机。面向 Agent 的热
路径变得更小，同时没有丢失 selected todo 或它的血统；monitor 转换在实质 writeback 之前不再
消耗 quota；terminal todo/vision 状态变得更显式。几个大型 CLI 模块沿现有归属边界切分，而不是
用并行框架替换。

代表性变更：

- [#1694](https://github.com/huangruiteng/loopx/pull/1694) 压缩了 quota todo 摘要，
  [#1731](https://github.com/huangruiteng/loopx/pull/1731) 直接暴露 selected todo。
- [#1764](https://github.com/huangruiteng/loopx/pull/1764) 在 quota 压缩中保留了 due monitors；
  [#1769](https://github.com/huangruiteng/loopx/pull/1769) 规范化了 agent vision 生命周期状态。
- [#1774](https://github.com/huangruiteng/loopx/pull/1774) 在不改变公开状态机的情况下缩减了
  todo CLI 模块预算。
- [#1855](https://github.com/huangruiteng/loopx/pull/1855) 修复了实质 monitor 转换后的 quota
  spend。

### 验证与失败归因改进

全公开 smoke 扫描成为常规 release gate，带并行分片与针对 git 重负载检查的显式处理。Benchmark
与 host 路径也为不可用 sandbox、远程 runtime、setup 依赖与缺失的分数证据增加了更快的 fail-fast
归因。这些检查不能替代真实的长程验证，但它们让一次失败运行在又一次昂贵尝试之前更容易分类。

代表性变更：

- [#1727](https://github.com/huangruiteng/loopx/pull/1727) 修复并并行化了全公开 smoke runner。
- [#1743](https://github.com/huangruiteng/loopx/pull/1743) 恢复了可靠的全公开 smoke 覆盖。
- [#1803](https://github.com/huangruiteng/loopx/pull/1803) 在 Codex sandbox 无法执行时迅速失败。
- v0.2.0 release 通过了全部六个公开 smoke 分片、一次 539 项检查的本地公开扫描与一次 17 表面的
  premerge canary。
