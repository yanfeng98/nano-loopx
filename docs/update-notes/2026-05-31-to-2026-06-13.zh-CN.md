# 每两周更新说明：2026-05-31 至 2026-06-13

> [English](2026-05-31-to-2026-06-13.md)

## 来源边界

本说明概括从 2026-05-31 初始公开 scaffold 到 2026-06-13 的公开仓库历史。它使用公开 commit 与
PR 历史、已交付文档、示例与 smoke 测试。它不包含私有 operator 状态、原始 benchmark 证据、
私有链接、本地路径或凭证。

## 亮点

- 发布了初始 LoopX 控制面 scaffold，并收紧围绕本地状态、goals 与生成证据的公开边界。
- 引入项目连接、active-state 投影、global registry 同步、状态输出、运行历史与只读项目地图。
- 构建了第一批面向 operator 的表面：dashboard 资源、用户动作投影、reward/gate 表面与紧凑的
  状态证据。
- 交付了 quota 与 heartbeat 基础，包括 should-run 决策、spend 事件、no-spend 行为与
  heartbeat prompt 生成。
- 添加了 review 与 handoff 机制：review packets、仅 handoff 的载荷、active todo CLI、
  project-agent todo 契约与多 Goal 支持。
- 把早期现场经验转成公开契约、smoke 测试与面向贡献者的文档，而不是留作私有聊天记忆。

## 交付内容

### 公开 Scaffold 与边界

仓库从一个最小公开 scaffold 发展成结构化的本地控制面。早期工作聚焦于把活跃 goal 状态、
runtime 状态、原始 benchmark 证据、本地路径与私有 operator 笔记排除在公开树之外，同时仍然
让产品行为通过文档与 smokes 可检视。

### 本地控制面

LoopX 获得了连接项目的首批 durable 原语：registry 条目、活跃 goal 状态、状态刷新、
run-history 记录、项目地图、goal ids 与 dashboard 可读的状态载荷。它们成为后续多 Agent 与
benchmark 工作流的基础层。

### Quota 与 Heartbeat 循环

该阶段引入了实践性的循环 scheduler 契约：`quota should-run` 回答一个 turn 能否产生有用工作，
`quota spend` 记录已验证的转换，heartbeat prompts 保持通用，使项目特定的 monitor 逻辑可以
住在 LoopX 状态中而不是 scheduler prompt 中。

### Review、Handoff 与 Todo 契约

LoopX 添加了 review-packet 生成、仅 handoff 载荷、agent todo 投影与可认领的公开贡献者任务。
这把产品从“记住这个 goal”转向一个可审查的范围化工作、证据、gates 与下一步动作队列。

## 验证与公开边界

第一个时间段强调边界扫描与 durable smokes。公开文档与示例被期望避免私有链接、原始日志、
实时的 `ACTIVE_GOAL_STATE.md`、凭证、本地文件系统路径与 benchmark trajectories。该边界仍然是
未来更新说明的规则。

## 下一时间段

下一个时间段聚焦于让 LoopX 对真实 Agent 工作流有用：benchmark 路由、Codex/Codex App 入口、
issue-fix 工作流、更丰富的任务投影与更健壮的 scheduler 行为。
