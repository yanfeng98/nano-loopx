# 每两周更新说明：2026-06-14 至 2026-06-27


## 来源边界

本说明概括从 2026-06-14 到 2026-06-27 的公开仓库历史。它使用公开 commit 与 PR 历史、已交付
文档、示例与 smoke 测试。它不包含私有 operator 状态、原始 benchmark 证据、私有链接、本地路径
或凭证。

## 亮点

- 把项目更名为 LoopX，并明确了产品形态：为长程 Agent 提供本地控制面，而不是隐藏的 executor。
- 加固了 benchmark 与 skills 工作流支持，涵盖路由契约、启动阻断项、生命周期收口与面向开发者的
  证据规则。
- 为 `/loopx`、`/loopx <goal>`、全局摘要命令、本地启动 dry-run 与 host 集成计划添加了
  Codex App 与 CLI 导向的入口。
- 把 issue-fix 从概念推进为工作流，包含 issue 元数据摄入、有序 todo 预览、验证证据与 PR
  review packet 就绪状态。
- 扩展了多 Agent 控制面投影：范围化 gates、任务图投影、冷路径 todo 详情、事件溯源状态规划
  与贡献者任务刷新。
- 通过 reset 策略、重复 monitor 检测、等待节奏简化、状态/quota 预算检查与集成的控制面 canary
  提升了 scheduler 安全性。

## 交付内容

### Benchmark 工作流加固

LoopX 为 SkillsBench、Terminal-Bench、ALE、SWE 风格路由与 benchmark 开发者工作流添加了更显式
的 benchmark 路由与生命周期契约。工作重点在于让 benchmark 运行可归因：启动阻断项被分类、
runner 前置条件被保留、case 本地生命周期纪律可测量，收口要求真实的 solver 或验证活动。

### Host 命令与 Agent 入口

产品为 Codex App 与 CLI 用户获得了更清晰的命令表面：`/loopx` 用于项目 bootstrap，
`/loopx <goal>` 用于显式 goal-start 规划，`/loopx-global-*` 命令用于全局摘要与 gates，以及本地
启动 dry-run 协议。近期路径仍是 skill 级 fallback；长期路径是带显式 project root、agent id 与
权限边界的 host 命令注册。

### Issue-Fix 工作流

Issue-fix 工作向完整的维护者工作流迈进：分类一个 issue，把它转成有序的 owner/todo 工作，运行
验证，捕获失败/通过证据，并产出 PR review packet。该工作流设计为在 issue 需要维护者判断时
保持人类 gates 显式。

### 任务投影与状态可靠性

控制面围绕 todos、gates、claims、近期运行与阻断项添加了更丰富的读取表面。任务图投影提供紧凑的
“它为什么卡住”视图，而冷路径 todo 详情把繁重的 per-todo 数据排除在热状态载荷之外。事件溯源
工作开始把 canonical todo/history 转向 append-only 记录，同时保持 Markdown 活跃状态作为人类与
Agent 的工作表面。

### 产品表面与公开文档

README 与文档工作明确了 LoopX 定位、showcase 目录、host 集成、入门帮助、贡献者任务板与
公开/私有边界。一些视觉 showcase 工作被刻意回退——当它们不足以留在 main 分支时——保持公开
表面作为更保守的 docs-first 入口。

### Scheduler 与控制面可靠性

Scheduler 工作加强了 reset 策略、重复 monitor 检测、per-agent frontier hints、等待节奏、
user-gate 精度，以及横跨 status、quota、review packet、event 与 read-path 行为的 canary 覆盖。
这些变更让长程 Agent 循环更不可能永远等待、清除错误的 gate，或者在缺乏可验证转换的情况下
花费算力。
